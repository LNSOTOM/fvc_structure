# Phase 3: 2D imagery and label handoff

## Status

This handoff records the historical method and how to inspect its products.
The config-driven `imagery_prep.py` implements its preparation steps; the
original scripts remain available as site-specific interactive research code.
Validate regenerated products against the original inputs and results before
using them in an analysis.

## Inputs and outputs

Provide a projected orthomosaic, its annotated grid polygons and FVC annotation
shapefiles, plus writable, separate output directories. Include all shapefile
sidecars (`.shp`, `.shx`, `.dbf` and `.prj`). Provide 1 cm reference tiles
covering the same tile IDs as the annotations, and the predictor tiles used by
the model. Record their CRS, transforms, extents and filenames; a filename or
resolution alone does not establish grid alignment.

The historical workflow documented in the
[label QA guide](step_3_label_quality/README.md) uses 30.72 m grid cells:

1. Select annotated grid cells and clip the orthomosaic to the cell envelopes.
2. Select multispectral bands 2, 4, 6, 8 and 10 for five-band predictor tiles.
3. Convert FVC polygons to `struct_id` classes 0–4.
4. Rasterize the polygons onto **1 cm reference tiles**, using `all_touched=True`
   and 255 for NoData.
5. Downsample labels to **5 cm** with nearest-neighbour resampling and remap
   classes 0–4 to 64–68; 255 remains NoData.
6. Assess the delivered polygons, 1 cm labels, 5 cm labels and predictor grids.

The preprint's five native classes are forb (FO, 0), woody debris (WD, 1),
grass hummock (GH, 2), shrub (SH, 3) and mallee (MA, 4). After remapping,
these are 64–68 in the 5 cm mask and corresponding LAS classifications.
NoData 255 is not a class. These five growth-form labels are distinct from the
paper's three-class model formulation; see the
[Phase 5 class conventions](../phase_5_3d_cnn_training/REPRODUCIBILITY.md#class-conventions).

The 1 cm reference is not necessarily the predictor grid. Some predictor tiles
are 5 cm and others 6 cm. A 5 cm label raster is not automatically aligned
with either: compare CRS, pixel size, origin and extent before combining them.
At 30.72 m, 30.72 / 0.05 is 614.4 pixels, so a 5 cm grid cannot preserve both
the exact extent and a whole number of pixels. Record the actual transform.

Outputs include five-band GeoTIFFs, classified shapefiles, 1 cm label
GeoTIFFs, 5 cm remapped label GeoTIFFs and QA CSVs. Keep large data outside
the repository; archive the exact input versions, output locations, parameters,
logs and software versions with the results.

## Environment

Use an environment with Python 3.10, GDAL Python bindings and `gdalwarp`,
Rasterio, GeoPandas, Shapely, NumPy, Pandas and SciPy. The repository's
[`environment.yml`](../environment.yml) lists these, but is not a locked
cross-platform environment. The shared `uv` environment for Phases 1–2 does
not include GeoPandas or the GDAL Python bindings. After activating the
environment to be used, check:

```text
python -c "from osgeo import gdal; import geopandas, rasterio, shapely, scipy; print('Geospatial imports OK')"
gdalwarp --version
```

For a separate minimal conda environment, for example:

```text
conda create -n fvc-phase3 -c conda-forge python=3.10 gdal rasterio geopandas numpy scipy pyyaml
conda activate fvc-phase3
```

Save `conda list --explicit` or the equivalent environment export with each
run; exports may be platform-specific. Use Windows paths in Windows Python and
Linux/WSL paths in Linux/WSL Python.

## Preparing the historical products

From the repository root, copy `configs/imagery_prep_job.example.yml` to
`configs/imagery_prep_job.local.yml` within the Phase 3 directory. The
following command works in Linux/WSL and PowerShell:

```text
cp phase_3_2D_imagery_prep/configs/imagery_prep_job.example.yml phase_3_2D_imagery_prep/configs/imagery_prep_job.local.yml
```

Edit every path in the local config. Link each output directory to the
following stage's input directory. `rasterize.reference_dir` is the directory
containing the **1 cm** reference TIFFs; `reference_pattern` must match their
names, using `{id}` for the trailing numeric tile ID. For example,
`tiles_multispectral_{id}.tif` matches `tiles_multispectral_26.tif`.
Use an orthomosaic at the intended predictor resolution for `tile`; the 1 cm
reference tiles are separate inputs and are not generated by this job.
In YAML, quote Windows paths with single quotes (for example
`'I:\data\reference'`) so backslashes are treated literally.

Do not assume `raw` and `stacked` 1 cm tiles use the same origin. For example,
the saved DD0001 tile 109 label grid matches the supplied raw 1 cm reference,
not the stacked 1 cm reference. Select the reference that matches the
historical labels or the grid specified by your analysis.

Run all five stages in order from the repository root:

```text
python phase_3_2D_imagery_prep/imagery_prep.py --config phase_3_2D_imagery_prep/configs/imagery_prep_job.local.yml --stage all
```

This runs without pausing between steps. Review the messages, including
excluded or unrecognized classes, and inspect the outputs afterwards. To inspect
each step before continuing, run the same command separately, replacing
`--stage all` with `--stage tile`, `--stage stack`, `--stage classify`,
`--stage rasterize` and `--stage downsample`, in that order.

The program refuses to overwrite existing output files and stops on errors. If a batch fails after
writing some files, inspect its messages and use a new empty output directory
for a retry. Preserve the console output as a run log.

Important details:

- Tiling filters `annotated = 1` by default, uses the `id` field and clips to
  feature envelopes. IDs must be unique non-negative integers. Grid and
  orthomosaic CRS must agree. Outputs are named `tiles_multispectral.<id>.tif`.
- Stacking selects bands 2, 4, 6, 8 and 10 and requires at least 10 input bands.
- Classification uses `structure` first, then other candidate type fields.
  Excluded and unrecognized types are removed and logged; mapped types are
  case-sensitive. Unlike the legacy script, a missing type field is an error,
  rather than silently assigning every polygon to class 1. Review the counts
  and warnings; see the QA guide for the low-site annotation discrepancy.
- Rasterization requires 1 cm references in a projected CRS with metre units
  matching the annotations. Overlapping polygons are resolved in input row
  order, as in the original script. Verify annotation versions and overlap.
- Downsampling matches the integer batch script's 5 cm nearest-neighbour grid
  and remapping. It does not align labels to the predictor grid. The separate
  legacy float script uses bilinear resampling and is not used for these labels.

The original scripts under `step_1_orthomosaic_to_tiling` and
`step_2_structure_2D_labels` still contain hardcoded paths and multiple
executable example cells; do not run them unedited as standalone programs.
This implementation does not claim to recreate a published dataset. In particular,
the original annotation versions and reference grids must be established
before comparing regenerated labels with historical results.

As a check, tile 109 at DD0001 was regenerated using its FVC annotations and
the raw 1 cm reference: the classified polygon IDs and geometry order matched
the saved classified shapefile, and the 1 cm and 5 cm label arrays and
transforms matched the saved rasters exactly. This single-tile check does not
establish equivalence for other tiles or sites.

## Run label QA

From the repository root, using the activated geospatial environment, replace
the placeholders below with **directories containing the files**, not their
parent directories:

```text
python phase_3_2D_imagery_prep/step_3_label_quality/label_qa.py --site example --shp-dir "/path/to/classified-shapefiles" --raster-dir "/path/to/1cm-labels" --downsampled-dir "/path/to/5cm-labels" --image-dir "/path/to/predictor-tiles" --output-dir "/path/to/qa-output"
```

On Windows, replace the quoted paths with Windows paths such as
`"I:\path\to\classified-shapefiles"`. Use `--tiles 26` for a small first
check, replacing `26` with an available numeric tile ID. The script matches
files by their trailing numeric ID and writes `example_qa_summary.csv` and
`example_qa_issues.csv`. Inspect both: missing optional inputs leave measures
blank rather than failing. The QA guide describes the metrics and known
historical label/predictor alignment and annotation-version issues.
